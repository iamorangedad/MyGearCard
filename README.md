# MyGearCard

把照片里的装备做成一张对战收藏卡（名称、HP、画面、招式），再提交印刷和邮寄订单。

卡面由服务端绘成 **744×1040** 的 PNG，按 300dpi 印刷就是标准卡牌尺寸 **63×88mm**。预览和下载的是同一张印刷文件。

## 启动

```bash
./run.sh
```

浏览器打开 <http://127.0.0.1:8080>。

模型地址、密钥、步数和价格都在部署时配置：复制 `.env.example` 为 `.env`，或直接写进进程环境变量。页面里不能改这些值。

## 两种出图方式

识别照片、撰写招式，走的是 OpenAI 兼容的对话接口。出图有两条路：

1. **本地文生图**
   - Stable Diffusion WebUI / SD.Next：`MYGEAR_LOCAL_IMAGE_BACKEND=a1111`，地址填 `http://127.0.0.1:7860`，启动时加上 `--api`。
   - 其他 OpenAI 兼容图像服务：`MYGEAR_LOCAL_IMAGE_BACKEND=openai`，地址要带 `/v1`，并填写模型名。
   - 视觉模型常见做法是本机 Ollama：地址 `http://127.0.0.1:11434/v1`，模型名用已拉取的视觉模型，例如 `llava`、`qwen2.5vl`、`moondream`。
2. **外部 API**
   - 同样是兼容接口。OpenAI 默认是 `https://api.openai.com/v1`，图像模型如 `dall-e-3`，视觉模型如 `gpt-4o-mini`。
   - SiliconFlow、智谱等只要提供 `/images/generations` 和 `/chat/completions`，把地址和模型名换掉即可。

模型没启动时，选 **原图排版**：不调用大模型，把上传的照片嵌进卡框，一样能下单。页面上的「笔记本 / 键盘 / 汽车」是内置示例图。

这台设备内存有限，网页进程本身不加载扩散模型，只去调用你已经部署好的服务。

## 订单

用户站点有两个页面：

- <http://127.0.0.1:8080/> 制作卡牌，生成后在同一页填写地址下单
- <http://127.0.0.1:8080/orders> 我的订单，只查看进度

管理员的印刷工坊是另一个页面：<http://127.0.0.1:8080/workshop>。它和「我的订单」读写同一份订单：待印刷 → 印刷中 → 已发货（填写运单号）→ 已完成。

当前版本**不会**自动调用印刷厂或快递公司，只负责把印刷文件和地址收齐。单价默认 29 元（`MYGEAR_CARD_PRICE_CENTS=2900`），运费 12 元（`MYGEAR_SHIPPING_CENTS=1200`）。

服务没有登录。密钥写在环境变量里，照片和收件地址在本机 `data/` 目录。不要把 8080 端口直接暴露到公网。
